## 2. 韌性三題：腳踏車版（W8 第 10 頁）

| 題目 | 回答 | 平台裡看得到的地方 |
| --- | --- | --- |

### 5.1 GitHub

Yu 沒有平台的 commit 紀錄，這是事實，不補也不偽造。從 W11 開始，開一個 Yu 自己的 repo 放本課的工作：

| 資料夾或檔案 | 內容 | 對應工作 |
| --- | --- | --- |
| `README.md` | 專案介紹、平台來源說明、本課 Yu 負責的部分 | R7 |
| `spec.md`、`docs/plan.md` | 規格與規劃 | — |
| `docs/ai-log.md` | Yu 自己使用 AI 的紀錄 | 5.2 |
| `survey/` | 問卷題目、匯出資料（去識別化）、Python 分析程式 | R2 |
| `eval/` | 40–60 則標註樣本、比對平台結果的 Python 程式、正確率報告 | R5、R9 |
| `docs/test-log.md` | 驗收條件 A1–A11 測試紀錄與發現的問題 | R6、R8 |
| `docs/progress/` | 每週進度報告 | — |

做法：
1. 每項工作開一個分支（例如 `feat/survey-analysis`、`eval/labeling`、`docs/test-log`），完成後用 PR 合併
2. 不 fork 平台的 repo，避免顯示其他人的帳號，或讓平台的 commit 被誤認成 Yu 的
3. 評分方式以助教的說明為準；可以先問助教：「用自己的 repo 放本課的驗證與文件工作，可以嗎？」

## 6. 參賽簡報規劃（範例簡報＋競賽四段架構）

| 頁 | 段落 | 標題方向 | 內容 |
| --- | --- | --- | --- |
| 01 | 封面 | 中大校園快報 | 隊名、Yu 的系級 |
| 02 | ① 問題／需求 | 腳踏車一直被偷，卻沒人追 | 具體情境＋三個困擾；問卷數字 |
| 03 | ② AI 應用 | 我怎麼用 AI | 做什麼／用了哪個 AI／AI 幫了什麼；分清楚作品內 AI 和開發用 AI |
| 04 | ② AI 應用 | AI 整理，規則把關，人來決定 | spec 第 4 節分工表 |
| 05 | ③ 解決方案 | 從一則貼文到一個系列 | 快報、系列分析、改善追蹤 |
| 06 | ③ 解決方案 | 運作流程 | spec 第 5 節流程圖 |
| 07 | ③ 解決方案 | 成果展示：腳踏車失竊系列 | 截圖，標「示範資料」 |
| 08 | ④ 成果與影響 | 系統已可實際運作 | 正式站真實事件數、改善進度、成績單；Demo 影片 |
| 09 | ④ 成果與影響 | 影響力 | 實測數字＋預期效益（標「預期」） |

第 03 頁草稿：

| 做什麼 | 用了哪個 AI | AI 幫了什麼 |
| --- | --- | --- |
| 整理快報、找規律（作品功能） | OpenAI gpt-5-mini（15 個 Skill） | 摘要、歸系列、提出可能原因 |
| 寫程式 | Claude Code（平台開發時使用） | 前後端程式、除錯 |
| 整理規格 | Claude | 對照計畫書、講評與平台，整理 spec 與 plan |
| 做簡報 | 可用 Copilot in PowerPoint | 簡報初稿 |

作品內 AI 不是 Microsoft 服務；做簡報可用 Copilot in PowerPoint（Microsoft 產品），對應競賽辦法第四點鼓勵使用微軟工具。

### 6.1 Demo 劇本（3 分鐘，示範站）

| 時間 | 畫面 | 重點 |
| --- | --- | --- |
| 0:00–0:30 | 快報首頁治安區 | 每起失竊一張卡，標「尚未查證」與「系列第 N 起」 |
| 0:30–1:30 | 腳踏車失竊系列 | 41 起、主要在宿舍區車棚；突增週；AI 規律標推測 |
| 1:30–2:15 | 改善前後比較 | 宿舍區加裝監視器後每週 3.3 起降到 1.6 起，但轉移到總圖前車棚 |
| 2:15–2:45 | 後台 What-if | 總圖前車棚比照加裝，標「假設情境」 |
| 2:45–3:00 | 韌性成績單 | 最弱的是「調適」 |

數字全部來自示範站假資料，簡報要標「示範資料」。

評審要記住的一句話：**失竊沒有消失，只是換了地方，而平台看得到。**

### 6.2 決賽可能被問的問題

| 問題 | 回答方向 |
| --- | --- |
| 腳踏車失竊是真的問題嗎？ | 問卷數字、訪談原話、正式站來源 |
| 學校已有校安中心，為什麼需要你？ | 把分散的學生聲音整理給既有單位，重點在追蹤改善 |
| AI 判錯怎麼辦？ | 未查證標示、規則決定公開、人工下架、驗證正確率 |
| 抓社群貼文合法嗎？個資呢？ | 只顯示摘要、不顯示原文與發文者、遮蔽個資；條款確認情形 |
| 件數變少就是措施有效嗎？ | 不是，只說「同期下降」 |
| 和一般 AI 摘要有什麼不同？ | 驗證計畫的三方比較結果 |
